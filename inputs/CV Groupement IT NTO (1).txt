### EXPÉRIENCE PROFESSIONNELLE

Depuis 04/2024 : Data Engineer | AGIRC-ARRCO, Paris
 Objectifs de la mission : Moderniser le système décisionnel en remplaçant la plateforme Teradata devenue coûteuse et rigide. Mettre en place un Data Lakehouse basé sur Apache Iceberg pour améliorer la scalabilité, la flexibilité, et la gestion des coûts. Reconcevoir les chaînes de traitement ETL existantes pour intégrer des sources massives de données hétérogènes. Automatiser la génération des scripts SQL et des logiques de jointure à partir d’un catalogue de métadonnées.
 Architecture et pipeline mis en place :
    1.  Architecture cible : Data Lake sur HDFS (Cloudera), Format de stockage Iceberg (via Spark SQL), PostgreSQL pour les usages analytiques (datamarts finaux), Pilotage ETL via DataStage 11.7 Cloud et scripts Spark/PySpark.
    2.  Zonage des données : ODS : ingestion brute depuis des fichiers Parquet, DTW : transformation et enrichissement avec logiques métiers, DTM : modélisation technique optimisée pour les analyses et le reporting, PostgreSQL : réplication des DTM pour les outils de BI.
Tâches :
     Migration Teradata → Iceberg : Analyse de l’existant : 500+ tables Teradata, logiques de MERGE, partitionnements, contraintes. Conversion automatique des DDL Teradata en DDL Iceberg (Spark SQL). Détection automatique des clauses PARTITION BY, PRIMARY INDEX, FK/NK. Mise en place d’un script Shell central (dapt_DDL_ODS_DTW_DTM.sh) pour transformer dynamiquement les schémas.
     Chargement et transformations Iceberg : Développement d’un module générique U+I (UPDATE + INSERT) sur Spark 3 pour chaque zone (ODS/DTW/DTM). Implémentation d’une stratégie MERGE avec auto-incrémentation via ROW_NUMBER() + MAX(ID_TECH_ADHS). Gestion fine des conflits de validation via une stratégie DELETE + INSERT.
     Génération dynamique de jointures FK/NK : Utilisation d’une table de paramétrage (COL_NK_ASSOCIEE) pour automatiser les jointures LEFT JOIN dans les étapes DTW/DTM. Génération conditionnelle des colonnes de jointure avec contrôle des types et du ORDRE_COLONNE.
     Automatisation & industrialisation : Génération automatique des scripts d’export PostgreSQL depuis Iceberg. Organisation des fichiers de logs par exécution avec traçabilité complète. Optimisation du volume disque grâce à un suivi des tailles HDFS (table par table).
     Tests & validation : Création de jeux de tests unitaires automatisés pour chaque pipeline (ODS > DTM > PostgreSQL). Validation croisée des agrégats entre Teradata et Iceberg. Monitoring de la volumétrie par table.
 Résultats obtenus : Réduction des coûts de licences Teradata >80%. Migration réussie de plus de 200 tables critiques vers Iceberg. Pipelines automatisés sur Spark 3 avec un monitoring fin des performances. Accès aux données DTM depuis PostgreSQL pour BI (temps de réponse < 2s). Documentation complète des scripts et de la configuration pour reprise facile par les équipes internes.
 Environnement technique : Teradata, Iceberg, Spark, DataStage 11.7, Cloudera, PostgreSQL, fichiers Parquet.
 Volume de données : 25 To en DTM, +100 Go/jour en flux entrants.
